WitchFlight 네트워크 최적화 검증

대상: 프로젝트에 설치된 Fusion 2.0.12 / Unity 6000.0.77f1, Host/Client 방식.

구현
- Player의 서버 전용 이동을 서버 + InputAuthority 예측 이동으로 변경.
- 이전 입력, 선회 속도, 부스트 재입력 잠금, 선택 빗자루 수치, 맵 복귀 경로를 Networked 상태로 복원.
- CharacterController 캐시를 재시뮬레이션/전진 시뮬레이션 배치 시작 시 복구.
- 카메라는 NetworkTransform의 렌더 처리 후 따라감. 원격 플레이어/서버 전용 투사체는 원격 타임라인 사용.
- 공격 생성/피해/패링/사망/포탈 승인은 계속 서버 전용. 예측 재실행이 RPC/타격을 중복 발생시키지 않음.
- 실제 Player 마나는 매 틱 유지. PlayerData 정보용 사본만 0.1초 단위로 묶고 최종 변화도 전달.
- 체력 UI는 HP 변화 알림으로 갱신. 체력바 위치 추적은 매 프레임 유지.
- 전투 Player/투사체의 전체 씬 검색을 Runner의 PlayerObject 조회로 교체.
- 레이/구체/겹침 검사는 버퍼 재사용. 버퍼가 가득 차면 전체 조회로 재검사하여 벽/피격 누락 방지.
- 깃발 낙하는 스냅샷 보간, 운반 중에는 모든 플레이어의 렌더가 끝난 뒤 위치 추적.
- 타격/스캔/시전 구체 및 비전 빔은 로컬 풀에서 재사용. 종류별 유휴 보관 상한 32개.
- 네트워크 투사체와 분신의 동적 메시에는 이 풀을 적용하지 않음.

자동 검사 (PowerShell 7, 저장소 루트, 각각 새 프로세스)
pwsh -NoProfile -File Tests/NetworkFlightRegression.ps1
pwsh -NoProfile -File Tests/CombatEffectPoolRegression.ps1
pwsh -NoProfile -File Tests/NetworkPresentationRegression.ps1

이 검사는 실제 소스의 메서드를 추출/컴파일하지만 Unity/Fusion 런타임은 일부 대체한다.
Unity 물리 충돌, 전송 손실, 실시간 FPS/보정량을 검증한 것으로 해석하면 안 된다.
전체 게임 C# 컴파일과 설치된 Fusion IL Weaver의 변환 검사도 별도로 통과했다.

실기 확인 순서 (아직 미실행)
1. Unity 재컴파일 후 같은 소스로 호스트/클라이언트 양쪽을 새로 빌드한다.
   Networked 레이아웃이 바뀌었으므로 이전 빌드와 혼합하지 않는다.
2. ChPrefab > Player > Enable Movement Prediction을 켠 상태로 비교한다(기본값 켜짐).
   한 명 테스트용으로 현재 Main의 MaxPlayerCount=1인 설정은 임의 변경하지 않았다.
   랜덤 매치는 기존 2명 규칙이고, 방코드 2명 테스트라면 인원 설정을 확인한다.
3. 두 실행본에서 호스트 역할을 번갈아 맡아 W/S 단계, Shift 유지/고갈/재입력,
   급선회, 수직 비행, 메뉴, 벽 충돌, 피격 넉백, 사망/리스폰을 확인한다.
4. 락온 완성/해제 발사, 각 마법/패링 쿨다운, 아군/자기 자신 기뢰 피해,
   벽 뒤 폭발 차단, 포탈 3초 쿨다운, 맵 자동 복귀, 고도 사망/깃발 낙하를 확인한다.
5. 반복 시전 후 효과 색/수명/위치가 이전 효과에서 남지 않는지 확인한다.
   Battle을 나갔다 다시 들어온 후에도 풀/카메라/로컬 플레이어가 갱신되는지 확인한다.
6. Fusion Network Conditions의 테스트용 지연/지터/손실을 단계적으로 올려 같은 조작을 반복한다.
   현재 저장된 운영 설정은 NetworkConditions.Enabled=false이며 수정하지 않았다.
   테스트가 끝나면 모의 네트워크 조건을 반드시 원복한다.
7. 에디터+빌드 한 PC의 공유 CPU/GPU 영향을 피하려면 최종 비교는 두 PC 빌드에서 수행한다.
   Unity Profiler에서 아래 마커와 GC.Alloc, CPU/GPU frame time을 함께 확인한다.
   WitchFlight.Player.Simulate
   WitchFlight.Player.AuthoritativeCombat
   WitchFlight.Projectile.Simulate
   Fusion Statistics에서 RTT/패킷 손실/재시뮬레이션 상태도 함께 기록한다.

의도적으로 유지한 것
- 이동 틱/송신 빈도를 임의로 낮추거나 높이지 않았고 조준 데이터를 거칠게 압축하지 않았다.
- 1대1에서 상대가 끊겨 보일 수 있는 공격적인 AOI 필터를 적용하지 않았다.
- 판정 체계를 바꾸는 지연 보상/새 KCC 도입이나 전용 서버 이전은 별도 설계와 실기 측정 대상이다.
