Witch's Flight 광장 — 첫 제작 구성

1. 뒤끝 데이터 설정
기존 LoginPlayerData 테이블에 다음 컬럼을 추가합니다.
  이름: openSpaceProgressJson
  형식: string (문자열)
  기본값: {}
기존 money, itemInventoryJson, 외형/칭호/목소리 컬럼은 그대로 사용합니다.
광장 입장 시 초기 재화는 다시 지급하지 않습니다.
생선 보유량, 도감 최초 등록일, 고양이 모션 해금, 안내 확인,
차단 목록, 처리 요청 이력이 이 문자열 안에 저장됩니다.
낚시 재화 보상은 OpenSpaceSettings의 enableCoinRewards를 켤 때만 지급합니다.
현재 기본값은 꺼짐입니다.

2. 제작 자산
Assets/Ch/ChprefabOpenSpace.prefab: 기존 ChPrefab에서 복사한 광장 전용 캐릭터.
Assets/Scenes/openspace.unity: 기본 지형, 입장 위치 4개, 낚시 자리 22개,
  고양이 쉼터, 코디 미리보기, 광장 UI가 배치되어 있습니다.
Assets/OpenSpace/OpenSpaceSettings.asset: 이동, 낚시 시간, 어종/확률,
  모션/가중치, 사운드, 광장 캐릭터/러너 프리팹 참조.
Main의 기존 OpenSpace 버튼: OpenSpaceEntry에서 광장 입장 연결.
원본 Assets/Ch/ChPrefab.prefab과 전투 입력 코드는 수정하지 않습니다.

3. Inspector 할당 원칙
UI는 openspace/OpenSpaceUI에 실제 오브젝트로 저장되어 있습니다.
ActivityPanel은 코디/고양이/가방/도감/메뉴 등에서 재사용하는 임시 UI입니다.
디자인 교체 시 OpenSpaceUI의 텍스트/버튼/행 참조를 다시 연결합니다.
확인창은 전체 화면 입력 차단 배경을 포함합니다.
지형과 UI는 플레이 중 생성하지 않습니다.
실시간 참여/퇴장에 필요한 네트워크 캐릭터와 Runner만 실행 중 생성합니다.
초기 배치는 편집용 블록아웃이며 최종 환경 아트가 아닙니다.
생선별 icon, 추가 효과음은 OpenSpaceSettings에서 지정할 수 있습니다.

4. 연결/저장 구성
Fusion Host/Client 전용 로비, 세션 최대 20명.
이동은 NetworkCharacterController의 입력 예측과 재시뮬레이션 사용.
낚시 자리 점유, 입질 시간, 포획 판정은 호스트가 결정합니다.
기존 전투 세션과 분리되어 있습니다.
현재 호스트 이전은 구현하지 않았습니다. 호스트 연결 종료 시
재입장/로비 복귀 안내를 표시하는 방식입니다.
낚시/먹이 요청은 로컬 OpenSpacePending에 먼저 기록하고,
같은 요청 ID와 동일 결과로 재확인하여 중복 지급을 방지합니다.
생선/도감/해금과 선택적 재화 보상은 한 계정 행에 함께 저장합니다.
기존 클라이언트 소유 데이터 구조를 사용하며, 서버 전용 경제 검증이나
동일 계정 여러 기기 동시 쓰기에 대한 트랜잭션 잠금은 포함하지 않습니다.
처리 지연 시 '결과 확인 / 재시도'를 사용합니다.

5. 조작
WASD 걷기 / 우클릭 드래그 시점 / 휠 확대·축소
E 고양이·낚시 상호작용 / T 캐릭터 감정표현
Enter 채팅 / ESC 입력·확인창·패널·활동 종료
광장 키 설정은 전투 키 설정과 별도로 저장합니다.
낚시 채팅 중에는 챔질 버튼을 사용할 수 있습니다.
고양이 교감은 누른 상태에서 위아래로 드래그합니다.

6. 검증 상태와 남은 제작 범위
사용자 요청에 따라 추가 플레이/빌드/멀티플레이 테스트는 실행하지 않았습니다.
실제 20명/21번째 입장, 지연·연결 종료·재접속, 한글 입력,
뒤끝 컬럼 연동과 저장 결과, 캐릭터·고양이 동작은 사용자가 확인합니다.
최종 환경 아트/생선 아이콘/개별 전용 모션의 완성도 조정은 별도 작업입니다.
플레이 경험 분석용 별도 광장 통계 로그 및 호스트 이전은 이번 구성에 없습니다.
고양이 코스튬, 자유 비행, 전투, 광장 구매/거래는 기획의 후속 범위입니다.
